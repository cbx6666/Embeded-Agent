一、架构目标

本版本的目标是实现一个可运行、可测试、可扩展的软件核心 MVP，用于在未接入真实硬件之前，先完成 Agent Runtime 的基础闭环验证。

二、分层设计

系统采用简化版五层设计：

1. Input Layer
负责接收外部输入并将其翻译为标准事件。当前实现包括 CLI 文本输入和 mock 状态输入。

2. State Layer
负责维护统一状态模型。当前已拆分为 `state/` 包，并进一步细分为用户状态、交互状态、专注状态、环境状态、冷却状态和记忆状态。

3. Decision Layer
负责根据事件和当前状态生成动作。主要由 `reducer.py` 和 `policy.py` 共同完成。

4. Action Layer
负责执行动作。当前实现包括控制台 speak/display 输出和专注计时器启动/停止。

5. Storage Layer
负责持久化状态快照与最近记忆。当前实现采用 JSON 文件存储。

三、核心模型拆分

当前核心模型已经明确拆分为三个包：

1. state/
负责定义状态模型。
当前进一步拆分为：
- user_state.py
- interaction_state.py
- focus_state.py
- environment_state.py
- cooldown_state.py
- memory_state.py
- agent_state.py

2. event/
负责定义标准事件模型。
这些事件来自真实世界输入或系统内部时钟，例如：
- user_text_input
- focus_start_requested
- focus_stop_requested
- user_presence_updated
- user_attention_updated
- user_emotion_updated
- environment_updated
- timer_ticked
- timer_finished

3. action/
负责定义标准动作模型，例如：
- speak
- display
- start_timer
- stop_timer
- none

四、adapters 的职责

adapters 层不定义核心领域模型，而是负责把不同输入源转换为统一事件，或把统一动作映射到具体输出。

例如：
- CLI 适配器将“开始专注 25 分钟”翻译为 focus_start_requested
- mock 适配器将 `/mock emotion tired` 翻译为 user_emotion_updated
- 后续摄像头适配器可以将“用户离席”翻译为 user_presence_updated
- 后续麦克风适配器可以将语音识别结果翻译为 user_text_input

五、主运行流程

接收输入
-> adapter 翻译为标准 Event
-> reducer 更新 AgentState
-> policy 生成 Action
-> output / timer 执行动作
-> memory 维护最近记录
-> storage 持久化

六、当前 MVP 范围

当前 MVP 已实现以下能力：

1. 用户文本输入后，Agent 必须返回一条响应；
2. 用户可通过“开始专注 X 分钟”进入专注模式；
3. 用户可通过“结束专注”停止专注模式；
4. 倒计时到期后自动结束专注并输出提醒；
5. mock 命令可更新 presence、attention、emotion；
6. 当用户 focused 且 tired 且已经专注一段时间时，可触发休息提醒；
7. 同类提醒具备基础冷却机制；
8. 最近事件、最近消息和专注记录可保存在状态中并落盘。

七、后续扩展方向

1. 扩展事件模型
继续增加来自视觉、语音、按键、环境传感器的标准事件。

2. 扩展动作模型
继续增加屏幕渲染、TTS 播报、LED 控制等标准动作。

3. 接入真实 LLM
在保持核心事件/状态/动作模型稳定的前提下，将 llm_service 替换为真实模型调用。

4. 替换存储层
将 JSON 存储升级为 SQLite 或其他嵌入式数据库。
